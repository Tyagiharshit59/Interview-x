# Implementation status vs. the master prompt

Legend: ✅ working and covered by code/tests · 🟡 working with limits (read the note) · 🔌 code is in place but needs an external service/credentials you must provide · ❌ not built

**Verification honesty:** the API and business rules have automated tests (`npm test`). The browser UI compiles and builds, and the WebSocket room is tested at the protocol level. **Real camera/microphone/WebRTC media, screen sharing, MediaRecorder uploads, Monaco collaboration and the mobile QR flow were not exercised in a real browser session in this build.** Expect to find UI bugs when you first run a live interview; budget time for that.

## Known limitations worth knowing
* SQLite is single-writer: fine for one server and modest load. Move to PostgreSQL (queries are plain SQL with `company_id` filters) before multi-instance deployment. Realtime rooms are in-memory, so run **one** API instance or add sticky routing + Redis pub/sub.
* Recordings and uploads live on local disk. Use object storage with lifecycle rules for production.
* Mesh WebRTC upload bandwidth grows with participants.
* Subscription expiry is evaluated on read; there is no scheduler that emails every state change.
